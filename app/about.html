A place for each memory.

A working city-map module for the AILT9019 travel-album project.

What works now

Explore 19 supported cities, filter/search in English or Chinese, select markers or the city list, and browse separate sample trip cards. Independent saved trip IDs determine visit counts and the 1 / 2–3 / 4+ brightness tiers. Demo edits persist in this browser; unsaved drafts survive city changes and reloads in the same tab. Example covers open in a photo viewer. Switch between the map and the selected city’s album with the Map / Album controls.

What comes next

The local backend already supports trip creation, editing, and photo uploads; a real cloud AI provider is not connected yet. Map city boundaries are approximate display footprints, not proof of a visit.

Try it

Choose Osaka, open “Try visit counting”, and add a sample visit. Edit a sample card: the count stays the same. Reload: the sample changes remain. Use “Reset sample album” to start over. All existing stories are fictional.

Data and privacy

The offline coastline comes from Natural Earth public-domain data, and city footprints from OpenStreetMap contributors. The default online map uses OpenFreeMap tiles and MapLibre; map tile requests reveal the currently viewed area, but our app does not send trip photos or notes to the map provider. Use ?map=local for a fully bundled map or ?map=google with a configured browser key. Example photos are credited to their photographers. API-mode trips and sanitised uploads stay in local SQLite/media storage. Cloud AI is not yet live.

Project record

Setup, proposed API contracts, data provenance and test evidence are in the private team repository (team/course access required). The map module is ready for team integration review; the full AI application is not complete.
