# Evaluation Plan

This file will become the evidence trail for the proposal, mid-term check, demo, and report.

## Rules before testing

- Use a fixed test set that was decided before checking results.
- Save the input, expected outcome, actual outcome, date, application version or commit, and evidence.
- Separate a factual error, an unavailable answer, a refusal, and a technical crash.
- Do not count a claim from an AI tool as evidence. Run the application and inspect the output.

## Minimum evidence set

1. A successful end-to-end run for the core user task.
2. An edge case that verifies error handling.
3. A fail-safe or refusal case tied to the project's ethics boundary.
4. A reproducibility run by a teammate or a fresh local environment.
