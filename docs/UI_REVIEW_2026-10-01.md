The 44 px recommendation is a touch-usability target, not a blanket WCAG AA failure assertion. Checkbox measurements alone are insufficient because its label is also clickable. We did not count it as a separate defect. The first exploratory script attempted to tap the centre of an SVG group bounding box (including non-interactive label space), which timed out; the actual circle tap succeeded. That automation targeting error is not evidence that pins are broken.

## Recommended direction for our next UI pass

**A personal travel atlas with photo-led trip cards.** Preserve the warm light palette and 2D city map; let the user's photographs carry the visual interest.

1. Desktop: map remains dominant; simplify the catalogue into compact search/filter controls; widen the selected-city album enough to show a cover image, date, title and short memory.
2. Mobile: map first; tapping a city reveals its cards immediately underneath or in an expandable bottom panel. Put city search in a compact searchable chooser, rather than a long list between map and memories.
3. Each trip: cover photo → date and title → short memory → open/edit. Multiple visits remain separate. Show AI generation as a deliberate action inside the trip editor, after its data notice, with user review before saving.
4. Progress: label the real scope, e.g. “5 of 19 supported cities visited”; keep exact visit counts alongside brightness. A short confirmation on first light-up is enough; avoid new badge/leaderboard systems for this MVP.
5. Priority: protect draft text and wrap long titles first; then connect actual photo cards with Angel and address mobile navigation. The UI reference work does not change the submitted proposal or assign extra backend/AI features.

## Reproduce the extra diagnostics

Start `python3 serve.py`, then run `tests/audit-browser.mjs` with the same optional `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `BASE_URL` and `EVIDENCE_DIR` variables as the existing browser suite. It records observations, including known defects, rather than presenting a green test verdict. It operates on fresh browser contexts and public sample data. Screenshots and JSON are written to the selected evidence directory. The separate third-party reference-browsing script was temporary and is not required for local diagnostics.
