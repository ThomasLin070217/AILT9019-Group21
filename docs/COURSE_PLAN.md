## What the project must be

Build a focused AI application for one specific user and one concrete task. The core workflow must run end to end on a student's own computer. We must show what the system does, where it was tested, and a limitation or failure case.

Use public, licensed, synthetic, or self-curated data only. Do not commit private data, passwords, API keys, `.env` files, or personal datasets.

## Final package

1. A project webpage that explains the problem, system, local setup, successful run, and repository link.
2. A three-minute presentation and a genuine demo recording. Show one successful run, one limitation or failure case, and what we learned.
3. A report of at most five pages, plus an unrestricted appendix, including Ethics and AI-use disclosure.
4. Participation in the Week 13 cross-team review and gallery.

## Proposal requirements

The Moodle proposal must be anonymous: no team number, member names, student IDs, emails, or other personal information in either content or filename.

The six required sections are Background, Project pipeline, Evaluation and test, Distribution and accessibility, Ethics and risks, and Checkpoints. The largest peer-review marks are Pipeline (12/50) and Evaluation (8/50), so these need a specific input → method → result path and measurable tests.

## Working rules

- Moodle is authoritative for releases and submissions.
- Ed is for questions and the required three-line Friday standup during Weeks 5–10.
- GitHub is the private project record. Commit working changes as we go.
- One team consultation is mandatory in Weeks 4–6 or Week 8, ideally before the revised proposal.
- Record AI assistance and verify every generated change by running and testing it ourselves.

## Assessment

The project is 60% of the course: report 15%, code and reproducibility 20%, webpage and demonstrations 25%. Participation is the other 40%, including self-paced work, tutorials, the consultation, mid-term check, proposal review, and final cross-team review.

A pass needs a working project, one genuine domain customisation, and complete deliverables. A distinction requires meaningful work beyond that baseline.
