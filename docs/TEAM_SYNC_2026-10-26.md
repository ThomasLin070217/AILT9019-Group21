Thomas's earlier standalone branch also contains a separate album/storage,
export and backup implementation. Those modules were **not** copied over:
running two different storage systems in one app would make visit counts and
saved records inconsistent. The shared product uses Owen's SQLite backend;
Thomas's useful model-call logic was adapted to that backend. His earlier live
AI evidence remains on the [standalone branch](https://github.com/ThomasLin070217/AILT9019-Group21/tree/ThomasLin070217/thomaslin070217/explore-local-files/tests/evidence/product/bailian).

The complete local path is city → saved trip → sanitised photo → editable card
+ persistent SQLite data → highlighted map area. **AI is optional:** the user
clicks **Write with AI**, reads a notice naming the city/date/title/notes/photos
sent, then confirms. The provider returns an editable draft or clarification;
review and save are separate actions. Without a configured provider, the app
returns an error without changing the trip.

## How to review the same version

```bash
git fetch origin
git switch main
git pull --ff-only origin main
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python3 -m backend
```

Open `http://127.0.0.1:8019/app/?mode=api&map=local`. The `map=local` option
avoids a tile-service dependency for the check. Run `.venv/bin/python -m pytest -q`
and `npm test` if Node.js 20+ is installed. Keep keys in `.env.ai.local` or the
server environment; never add them to Git or a screen recording. Send changes
as a focused PR against `main` so the team can inspect and test them.

The mid-term deadline is 26 October. The repository does not prove that Moodle
has received the ZIP, video and one-page Word status sheet; check that submission
separately rather than reporting it as done.
